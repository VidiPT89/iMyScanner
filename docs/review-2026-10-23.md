# Review, 2026-10-23

## Changes

- Metadata writes report failures and refuse to overwrite unreadable indexes. The detail screen rolls back rejected updates. Removed page images are deleted only after the new index is committed.
- Image batches no longer create pages for failed writes. Photo callbacks preserve selection order without concurrent array mutation. EXIF orientation is normalized, including older stored images.
- Crop editing and detection use the original image coordinate system. Handles use a named coordinate space, cannot cross adjacent edges, and invalidate pending automatic detection on manual movement. Four corners now drive perspective correction.
- Preview/rotation renderers use explicit image scales. PDF rasterization is bounded to 2400 pixels per side. Library thumbnails are decoded at thumbnail resolution.
- PDF/image exports fail visibly when a page cannot be read. Each share has an independent directory so equal titles cannot overwrite another share.
- OCR finishes even on Vision execution errors and discards stale results after an edit. Editing invalidates previously recognized text.
- ZIP writing rejects oversized entry names/counts and marks Unicode names as UTF-8.
- Removed unused editor APIs, page-reorder helper, unused state and unused color asset. README no longer claims a free-rotation/reorder UI that did not exist.

## Validation

- `sh scripts/test-core.sh`: 9 checks passed against actual models, ZIP and DOCX implementations. Includes legacy decoding, imported-file metadata, ZIP limits, independent exports, XML escaping and Portuguese text.
- `sh scripts/check-types.sh`: services/models/view models type-check for arm64 iOS Simulator; all app/view Swift files parse. One concurrency warning remains: non-Sendable storage captured by the background import closure. This is not a Swift 6 migration.
- `git diff --check`: passed.
- Full Xcode build attempted, but the managed environment prevents the SwiftUI macro plugin sandbox from launching (`sandbox_apply: Operation not permitted`). CoreSimulator service access also failed. UI type-checking, installation and device tests are therefore not certified by this review.

## Remaining validation and useful next work

1. Build in Xcode and test iPhone/iPad: camera and photo import, rotated photos, crop twice, OCR, sharing PDF/images/Word, deletion, relaunch and low-storage errors.
2. Run a large-document memory test. PDF import still holds the batch in memory; streaming each page directly to storage is the next performance improvement.
3. Add real page-reordering controls, searchable PDF export, and automatic OCR for Word export. Current Word export uses recognized text already saved on each page.
4. Add UI regression coverage and complete concurrency isolation before adopting Swift 6.

This review does not assert complete device coverage, App Store readiness, or the absence of every possible bug.
