# Review, 2026-10-23

## Changes

- Metadata writes report failures and refuse to overwrite unreadable indexes. The detail screen rolls back rejected updates. Removed page images are deleted only after the new index is committed.
- Image batches no longer create pages for failed writes. Photo callbacks preserve selection order without concurrent array mutation. EXIF orientation is normalized, including older stored images.
- Crop editing and detection use the original image coordinate system. Handles use a named coordinate space, cannot cross adjacent edges, and invalidate pending automatic detection on manual movement. Four corners now drive perspective correction.
- Preview/rotation renderers use explicit image scales. PDF rasterization is bounded to 2400 pixels per side. Library thumbnails are decoded at thumbnail resolution.
- PDF/image exports fail visibly when a page cannot be read. Each share has an independent directory so equal titles cannot overwrite another share.
- OCR finishes even on Vision execution errors and discards stale results after an edit. Editing invalidates previously recognized text.
- ZIP writing rejects oversized entry names/counts and marks Unicode names as UTF-8.
- Removed unused editor APIs, page-reorder helper, unused state and unused color asset. README no longer claims a free-rotation/reorder UI that did not exist.

## Validation

- `sh scripts/test-core.sh`: 9 checks passed against actual models, ZIP and DOCX implementations. Includes legacy decoding, imported-file metadata, ZIP limits, independent exports, XML escaping and Portuguese text.
- `sh scripts/check-types.sh`: services/models/view models type-check for arm64 iOS Simulator; all app/view Swift files parse. One concurrency warning remains: non-Sendable storage captured by the background import closure. This is not a Swift 6 migration.

## Second pass (same day)

### Changes

- Searchable PDF export: pages are drawn with `UIGraphicsPDFRenderer` at A4 width (595 pt, scan aspect ratio, full image resolution) with Vision OCR text drawn in invisible mode on top. Previously a 12 MP scan became a page over a metre tall, with no text layer.
- Word export recognizes pages that never went through "Extract Text", instead of exporting "no text" for them.
- Page reordering (Move Earlier / Move Later in the page context menu), as onboarding already promised. Logic lives in `ScanDocument.movePage(id:by:)`.
- Deleting a document from the context menu now asks for confirmation. It used to delete immediately and irreversibly.
- Thumbnails decode off the main thread and are cached. They used to be decoded inside `body`, for every page, on every re-render (each keystroke in the search or tag field). They are anchored to the top of the page.
- PDF import writes each rendered page to storage immediately instead of keeping every page of the PDF in memory as a `UIImage`.
- Orphaned page images and imported files (older than a day, unreferenced) are removed once at launch. Skipped when the index is missing or unreadable.
- Crop magnifier showed the wrong part of the image (the opposite quadrant, or nothing at all). Verified with an `ImageRenderer` test of the same modifier chain before and after the fix.
- The scan button no longer covers the last card. Export names share one sanitizer (`ScanDocument.exportBaseName`) that keeps accents. Resolved the `Sendable` warning (`DocumentStorageService` documented as `@unchecked Sendable`).

### Validation

- `sh scripts/test-core.sh`: 11 checks passed (adds export-name checks).
- `sh scripts/test-exports.sh` (new): 9 checks passed on the iPhone 17 Simulator (iOS 26.5). The script builds the real export/import services for the simulator and runs them with `simctl spawn`. It checks A4 page size, the searchable text layer through `pdftotext`, OCR text in the Word file, page moves and the streamed PDF import.
- `sh scripts/check-types.sh`: no errors or warnings. Debug and Release `xcodebuild` builds plus `analyze`: no warnings.
- Installed in the simulator with seeded documents: the list shows top-aligned thumbnails and launches without errors. Context-menu flows were not driven automatically (no UI test target).
